# Миллионники: разбор запроса кодом, районы и «что рядом» без внешних сервисов

Реализация плана из [TOP5_PARSER_TECH.md](TOP5_PARSER_TECH.md) — не для 5, а для **18 городов**:
- 16 миллионников: Москва, Санкт-Петербург, Новосибирск, Екатеринбург, Казань, Красноярск, Нижний Новгород, Челябинск, Уфа, Самара, Ростов-на-Дону, Краснодар, Омск, Воронеж, Пермь, Волгоград;
- 2 города, близких к миллиону: Саратов и Тюмень.

Список задаётся в `backend/geodata.CITIES`, добавить город — одна строка.

## Что сделано

| Часть | Файлы | Что даёт |
|---|---|---|
| Сборка геоданных из OpenStreetMap | `scripts/build_geodata.py` | Административные районы с границами, неофициальные районы и микрорайоны, метро, объекты «что рядом» (школы, детсады, поликлиники, парки и др.), крупные дороги и ж/д, признаки районов |
| Справочник мест | `backend/geodata/`, `backend/geodata/names.py` | Названия → город, район, неофициальный район, метро. Синонимы: МСК, Питер, Екб, Нск, Подмосковье, «Бутово» = Северное + Южное Бутово и т. п. |
| Разбор кодом | `backend/agent/rule_parser.py` | Простое сообщение разбирается без двух запросов к модели. Всё сомнительное уходит в модель |
| Встраивание и теневой режим | `backend/agent/understanding.py` (`_rule_parse`, `_shadow_compare`), `RULE_PARSER` | `off` / `shadow` / `on`. В `shadow` каждое расхождение с моделью пишется в журнал |
| Тип района | `backend/agent/districts.py`, поле профиля `district_type` | «Спальный», «престижный», «тихий» район. Метки считаются из данных, клиенту показывается список районов |
| Районы в запросе к Циану | `backend/sources/cian.py` (`learn_districts`, `district_ids`) | Циан фильтрует выдачу по id районов и микрорайонов. Id берутся из самой выдачи |
| «Что рядом» локально | `backend/geo.py` (`_local`) | В городах с геоданными — без 2ГИС и Overpass |
| Центр для всех миллионников | `backend/agent/pricing.center_distance` | «Ближе к центру» заработало там, где точки центра не было (10 из 16 городов) |

| Замер | `backend/telemetry.py` → `/api/metrics` | Счётчики `llm.<вид>`, `rule_parser.accepted/declined/shadow_agree/shadow_disagree`, `source.cian_page/twogis/overpass/poi_local` |

### Как разбор кодом решает, принять ли сообщение

Сообщение принимается, только если выполнены все условия:
- **Каждое слово понято.** Слово либо распознано (город, район, неофициальный район, комнаты, бюджет, вторичка/новостройка, оплата, «в центре», «ближе к центру», «спальный/тихий/престижный район»), либо служебное («хочу», «ищу», «квартиру», «в», «до»…).
- **Нет стоп-слов:**
  - отрицание и исправление: не, нет, кроме, а, но, передумал, лучше, вместо, точнее, хотя;
  - вопрос (знак «?», «сколько», «почему»…);
  - место не про квартиру: работаю/живу/учусь в, как в, из, переезжаем;
  - команды по выдаче и звонку: покажи, первую, сравни, позвони;
  - «ипотека» без ясности со взносом.
- **Места однозначны.** Один город или «X или Y». Районы из одного города, и этот город совпадает с городом профиля. Название, совпадающее с обычным словом («Советский», «Сокол»), принимается только после «в/на/район».
- **Нет открытой карточки,** на которую сообщение может быть ответом. Нет неподдержанных пожеланий в работе.

Во всех остальных случаях сообщение разбирает модель, как раньше. Результат разбора кодом — тот же объект `CHANGE_SCHEMA`, он проходит ту же проверку и фильтр инъекций, что и ответ модели.

### Как считается тип района

Подробно с порогами — в начале `backend/agent/districts.py`. Коротко:

| Метка | Как считается |
|---|---|
| **у центра** | В районе центр города, или центр района ближе max(2 км, 20 % радиуса города) |
| **спальный** | Дальше 40 % радиуса; мало офисов и магазинов; много школ и детсадов на км²; цена м² не выше средней по городу более чем на 15 % |
| **деловой** | Офисов и магазинов на км² больше, чем у 80 % районов, и район не дальше половины радиуса |
| **престижный** | Медиана цены м² по нашим объявлениям за 120 дней — не ниже 1,25 от средней по городу (минимум 8 объявлений) |
| **тихо** | Свойство дома, а не района: крупная дорога не ближе 200 м, ж/д не ближе 300 м |

Ручные поправки задаются в `districts.OVERRIDES`.

В поиске метки работают так:
- **«Спальный» или «престижный»** — агент говорит, в каких районах ищет: «Спальные районы — Казань (оценка по застройке, удалённости от центра и ценам): …». Запрос к Циану ограничивается этими районами, если их id известны. На карточке квартиры условие подписано «оценка по ценам и застройке».
- **«Тихо»** — пожелание: квартиры у магистралей не отсеиваются, а опускаются ниже в выдаче.

### Районы и Циан (проверено на живом Циане 06.11.2026)

- В выдаче Циана у каждого объявления есть районы с id двух уровней. Пример по Уфе: районы (`raion`: Советский — 311, Калининский — 306) и микрорайоны (`mikroraion`: Сипайлово — 820, Черниковка — 819, Затон — 802).
- Ссылка `…&district[0]=311&district[1]=820` сузила выдачу 2-комнатных в Уфе с 1209 до 261 объявления. Все найденные объявления — из Советского района и Сипайлово.
- Парсер запоминает id из каждой живой выдачи в `backend/data/cache/cian/districts.json`. Справочник наполняется сам: при подборах и ночном обходе.
- Если id хоть одного нужного района ещё неизвестен, фильтр в ссылку не ставится. Поиск идёт как раньше, с отбором по названию после загрузки. Так объявления не теряются.

## Как собрать геоданные

Без собранных данных всё работает как раньше. Разбор кодом при этом узнаёт только города (без районов), а тип района агент честно называет непроверяемым для этого города.

```bash
pip install -r requirements.txt                 # pymorphy3 + словари
.venv/bin/python -m scripts.build_geodata       # все 18 городов, 20–40 минут
.venv/bin/python -m backend.geodata             # что собрано
```

Полезные опции:
- `--cities Казань "Нижний Новгород"` — собрать часть городов;
- `--force` — пересобрать готовые;
- `--mirror https://…/api/interpreter` или переменная `OVERPASS_URL` — свой сервер Overpass;
- `--roads` — у готового города пересобрать только крупные дороги и ж/д (несколько минут вместо получаса).

Если сервер Overpass не успел выполнить запрос, он всё равно отвечает «200 OK», но с частью данных и пометкой `remark: runtime error`. Скрипт считает такой ответ ошибкой и идёт к следующему зеркалу. Если после сборки у города нет ж/д или меньше 500 крупных дорог, скрипт предупреждает об этом.

Уже собранные города при повторном запуске пропускаются, поэтому после сбоя сборку можно просто запустить ещё раз.

**Важно для России.** 06.11.2026 из российской сети зарубежные серверы Overpass не отвечали, а зеркало VK (maps.mail.ru) отдавало 504. Если сборка зависает или пишет «Overpass недоступен», включите VPN. Обновлять данные стоит раз в месяц.

Файлы появляются в `backend/geodata/cities/`. Их нужно закоммитить:
- `<город>.json.gz` — справочник;
- `<город>.poi.json.gz` — объекты и дороги.

Данные © участники OpenStreetMap, лицензия ODbL: при показе источника на сайте нужна подпись.

## Режим `RULE_PARSER`

| Значение | Что происходит |
|---|---|
| `shadow` (по умолчанию) | Решает модель. Разбор кодом работает параллельно, и в журнал пишется `rule_parser` с `shadow_agree` или `shadow_disagree` и значениями обеих сторон |
| `on` | Простое сообщение разбирается кодом без двух запросов к модели. Остальные — моделью |
| `off` | Разбор кодом выключен |

**Как включать.** Неделю работать в `shadow` и смотреть `/api/metrics` → `rule_parser.shadow_agree` и `shadow_disagree`. Разбирать каждое расхождение по журналу (`"event": "rule_parser"`). Переключать на `on`, когда расхождений нет. Цель из плана — совпадение от 99 % и 0 ложных принятий.

## Ограничения

- **Разбор кодом консервативен.** Всё, кроме простых сообщений, по-прежнему идёт в модель. Станции метро в профиле не хранятся: «у метро Сокол» разбирает модель.
- **Метки районов — оценка.** «Престижный» без наших цен не ставится. Для нового города сначала нужны объявления: после первых подборов и ночного обхода.
- **Границы и неофициальные названия берутся из OpenStreetMap.** Где OSM неполон, справочник тоже. Поправки — в `names.py` и `districts.OVERRIDES`.
- **Фильтр по районам в ссылке Циана включается,** только когда id всех нужных районов уже встретились в выдаче. В первые дни по новому городу поиск идёт без него.
- **2ГИС и Overpass остаются для городов без геоданных.** Кеш проверок по каждому объявлению на 30 дней был и раньше. Отдельный кеш по координатам не делал: в 18 городах внешние запросы почти не нужны.
- **Классификатор типа сообщения** (этап 7 плана) не сделан. Для него нужны размеченные логи, а модели с HuggingFace из моей среды недоступны. Теневой режим как раз копит эти данные.
