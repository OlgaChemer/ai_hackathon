# Ценовые ориентиры и границы цены

## Причина расхождения

Ценовой ориентир превращал пожелание «ближе к центру» в обязательный радиус
5 км и добавлял ЦАО к запросу по Москве без явного выбора округа. При этом
обычная подборка и мастерская использовали другой набор объявлений. В проверенном
диалоге старый срез из 49 объявлений давал медиану 167,9 млн ₽.

Теперь пожелание остаётся пожеланием. Радиус применяется только как обязательное
условие; округ источника ограничивается только явным выбором клиента. Ориентир
объединяет свежие страницы источника с реальными объявлениями общей базы за
последние семь дней, удаляет дубли по ID и проверяет условия. Свежая версия
объявления заменяет сохранённую. Использование сохранённых данных отмечается
в отчёте об охвате, это по-прежнему ограниченная выборка, а не весь рынок.

Границы бюджета при исследовании применяются только когда это запрошено.
Режим апартаментов и обязательные условия сохраняются. Новая версия политики
выборки инвалидирует старые ценовые кэши; устаревшие числа не передаются в
контекст ответа как актуальные. Исторические сообщения не переписываются.

Общий модуль `backend/market_statistics.py` вычисляет числовые метрики агента
и мастерской. Одинаковые объявления дают одинаковые числа. Выборки могут
различаться: мастерская ограничивает размер снимка, а ценовой ориентир может
исследовать рынок без бюджета. Поэтому агент сообщает, что цифры относятся
к отдельной выборке, а не только к карточкам на экране.

Проверка на сервере с профилем исходного диалога: 609 прошедших условия объявлений,
медиана 29 900 000 ₽, средняя цена 61 965 845 ₽. Разницу со средней объясняет
дорогой хвост; дорогие реальные квартиры не исключаются ради удобных цифр.
Это результат конкретной проверки, не постоянный ориентир для Москвы.

## Ползунок

По продуктовому правилу нижняя граница подтверждаемого диапазона составляет
не менее 70% верхней. При 27 млн ₽ начальное значение — 18,9 млн ₽.
Изменение верхней границы сохраняет выбранную пропорцию, нижний бегунок не может
расширить коридор за −30%. Подпись рассчитывается по реальным значениям.
Точная цена квартиры сохраняется без округления до шага управления.

Сервер нормализует подтверждение из старого интерфейса с нулевой нижней границей.
Расчёт 70% округляется вверх до рубля, чтобы округление не расширяло коридор.
Свободный исследовательский запрос без бюджета остаётся возможным.

## Проверки

- Регрессии мягкого/обязательного центра, явного округа, бюджета, апартаментов,
  объединения сохранённых объявлений и инвалидирования старого кэша.
- Совпадение числовых метрик агента и мастерской на одном наборе данных.
- Браузерные проверки на 1440 и 390 px: точные цены, начальное значение
  18,9 млн ₽, подпись 30%, ограничение нижнего бегунка и изменение верхнего.
- Проверка выбора конкретной квартиры без общего бюджета и продолжения
  ипотечной анкеты после подтверждения её цены.
- Общий выпускной прогон Python, JavaScript и проверки нагрузки состояния.
