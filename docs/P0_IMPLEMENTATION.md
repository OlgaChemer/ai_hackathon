# P0: реализация и проверки

P0 сохраняет состояние диалога, решения и результаты операций до отправки
критических событий клиенту. Один основной агент и 18 бизнес-инструментов
сохранены. Промпт инфографики обновлён: агентский цикл, инструменты и выключенный
планировщик показаны явно.

## Обязательный объём

- Единое представление условий и одинаковая политика unknown.
- Очередь команд диалога, идентификаторы и защита от повтора; каждый FAQ получает ответ.
- Ревизии задания и снимка; устаревшая асинхронная работа не публикует актуальный результат.
- Сохраняемый снимок всего критического процесса, включая поиск, отметки, звонки,
  согласованные цены, выбранный объект, ожидаемые и принятые решения.
- Атомарное сохранение снимка, результатов операций и событий перед SSE.
- Критическая ошибка БД останавливает подтверждение успеха; cache остаётся best effort.
- Восстановление карточек и безопасное продолжение; неопределённый исход звонка
  требует сверки, реальный звонок не повторяется автоматически.
- Структурированные причины ошибок; технический сбой не становится пожеланием клиента.

## Совместимость

Остаются одно приложение, SQLite, один основной агентский цикл и 18 инструментов.
Старые профили/история читаются через адаптер. Миграция аддитивная; пользовательская
БД не заменяется. Новая библиотека морфологии и географические полигоны не входят в P0.

## Последовательность

1. Снимок, журнал операций и транзакционная фиксация; проверки отказов и восстановления.
2. Долговечные решения, идемпотентные команды, очередь FAQ и восстановление ожиданий.
3. Ревизии и отмена устаревших результатов; независимые снимки долгой работы.
4. Канонические условия, единая проверка и типы ошибок.
5. Совместные unit/API/browser сценарии, настоящая модель на изолированном стенде,
   резервная копия, безопасная выкладка и проверка публичного сайта.

## Приёмка

Дубликат команды не повторяет эффект. Два быстрых вопроса дают два ответа.
Новое условие во время поиска не получает старую подборку как актуальную.
Перезапуск на каждой карточке сохраняет объект, цену и допустимое решение.
Отказ записи не отправляет критическое событие. Эквивалентные условия имеют
одинаковые оценки; отмена снимает все представления. Прежние регрессии сохранены.

## Где реализованы гарантии

| Гарантия | Реализация |
| --- | --- |
| FIFO и квитанции команд | `backend/agent/commands.py`, транзакции `backend/db/repo.py` |
| Снимок только из данных | `backend/agent/state.py`, восстановление `session.py` |
| Сохранение перед доставкой | `backend/agent/persistence.py` |
| Независимая асинхронная работа | `Session.fork`, проверка ревизии в `Session.flush` и цикле |
| Продолжение того же инструмента | `backend/agent/operations.py`, долговечная карточка решения |
| Известный/неизвестный исход звонка | checkpoints в `actions/deal.py`, восстановление в `loop.py` |
| Единая проверка дополнительных условий | `backend/agent/conditions.py`, адаптер прежних полей |
| Различение сбоя и неподдержанного пожелания | `understanding.py`, `profile_patch.py`, структурированные результаты действий |

`tests/test_p0_state.py` проверяет отказы до записи и после SQL flush, отсутствие
SSE при откате, устаревшего владельца, миграцию прежней SQLite, повторы после
перезапуска, восемь видов карточек, подборку с отметками, известный и неизвестный
исход звонка, устаревшие поиск и ответ модели и сохранение очереди FAQ при сбое БД.

Полные снимки процесса создаются этой версией. Старые профили, история и последняя
подборка читаются через адаптер; данные, которые старая версия вообще не сохраняла,
не выдумываются при восстановлении. Настоящие телефонные вызовы в этих прогонах
не выполнялись: переговоры проходили с ИИ-продавцом, восстановление телефонии
проверялось на сохранённых состояниях и подменённых интеграциях.
