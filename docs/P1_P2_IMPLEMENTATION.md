# P1 / P2: объём и приёмка

Продолжение архитектурного аудита после P0. Сохраняются монолит, SQLite,
один основной агентский цикл и 18 бизнес-инструментов.

## P1

- Единый исполняемый каталог возможностей: аргументы, обязательность,
  допуски, причины отказа, зависимости, инвалидирование и контекст FAQ.
  Неизвестный инструмент без политики запрещён.
- Охват поиска: источники, страницы, свежесть, выполненные/неизвестные
  проверки, бюджет, причины неполноты. Отказ страницы не означает конец рынка.
  Совпадение имеет доказательство; пустой результат относится к проверенному охвату.
- Повторяемые регрессии ошибочных ответов, генерируемые последовательности,
  отложенные формулировки, повторные прогоны модели и версии в отчётах выпуска.
- Право телефонной операции связано с владельцем, квартирой и ID решения;
  квоты и синтез ограничены операцией. Общие SIP-учётные данные нельзя считать
  одноразовыми: публичная телефония не открывается автоматически.

## P2

- Ограниченные очереди и память процесса; промежуточный прогресс объединяется.
  Медленный SSE-клиент восстанавливается из сохранённых событий без потери фактов.
- Обновления UI и решения не ждут озвучку, телефонное аудио или декоративную паузу.
- Явные версионированные миграции с журналом и проверкой совместимости.
- Раздельные liveness/readiness и состояние отдельных возможностей.
- Метрики задержек, очередей, разбора, сохранения, непроверенных результатов
  и восстановления без клиентских текстов и меток высокой кардинальности.
- Измерение нагрузки на текущей SQLite; смена БД/несколько workers только
  при подтверждённой необходимости, без добавления инфраструктуры по умолчанию.

## Приёмка

Все прежние регрессии P0 сохраняются. Дополнительно: согласованность каталога,
закрытый допуск нового инструмента, различимые неполный/пустой/недоступный поиск,
запрет чужого/устаревшего телефонного разрешения, квоты TTS, медленный SSE,
неблокирующая озвучка, обновление старой SQLite и отказ при неизвестной миграции,
различение живого процесса и недоступной возможности, ограниченность метрик,
повторный и отложенный экзамен модели. Выкладка — после изолированного стенда
и резервной копии; реальные телефонные вызовы при испытаниях не выполняются.

## Статус

Реализация и приёмка в работе.
