Перед обновлением сохраняются текущий commit/branch, `git diff --binary`, незакоммиченные файлы, `.env` и консистентная копия SQLite через `sqlite3.Connection.backup()`. Резервные копии лежат вне проекта в `/home/admin/deploy-backups/`, доступны только владельцу. Серверные правки не уничтожаются: перед сменой коммита они сохраняются в stash.

После локальных проверок и `git push origin all_branch`:

1. На сервере получить ветку и проверить, что ожидаемый коммит доступен. До остановки сайта проверить его в отдельном `git worktree` в `/home/admin/deploy-preflight/<commit>`; тесты запускать с ограничением `timeout 90`.
2. Остановить `domclick-agent.service`, сохранить оставшиеся локальные правки в stash, переключиться на конкретный commit в detached HEAD.
3. Проверить зависимости в `.venv`, выполнить модульные тесты. В `.env` выбрать `LLM_PROVIDER=gigachat`; ключи сохраняются серверные, проверка TLS включена. Для публичного HTTPS-сайта используется `COOKIE_SECURE=true`.
4. Запустить сервис, проверить `/api/health`, `/api/map` и открытие главной страницы. При ошибке запуска вернуть предыдущий commit и `.env` из резервной копии.

## Живые проверки

```bash
.venv/bin/python -m tests.e2e.live_site --base https://domclick-agent.cikada-tech.com
.venv/bin/python -m tests.e2e.live_site --base https://domclick-agent.cikada-tech.com --case cash --until sign
```

Проверки используют настоящий GigaChat и настоящие объявления, расходуют квоты и сохраняют тестовые диалоги. Три сценария по умолчанию доходят до подборки: наличные/оба рынка, ипотека/вторичка, накопления/семья/новостройки. Дополнительно проверяются история, отказ на инъекцию и отдельный ответ на вопрос. Режим `--until sign` проходит демо-сделку с ИИ-продавцом: телефонные номера не набираются.

Кэшированный клиент GigaChat ставит генерации в очередь: основной агент, ответы на вопросы и переговоры используют один поток на процесс. Это соответствует [ограничению API для физлиц](https://developers.sber.ru/docs/ru/gigachat/limitations). При нескольких uvicorn workers или другом приложении с тем же ключом нужен общий ограничитель; текущий сервис работает одним процессом.

Версия с ограниченной очередью использует по умолчанию `GIGACHAT_QUEUE_SIZE=6`, `GIGACHAT_QUEUE_TIMEOUT_S=25`. Общий срок вызова модели — `LLM_CALL_TIMEOUT_S=60`; активного хода — `AGENT_TURN_TIMEOUT_S=120`, без времени ожидания человека. Значения по умолчанию работают без изменения серверного `.env`; после получения новой версии нужен перезапуск backend. Эта версия вместе с общей оболочкой развёрнута 02.11.2026; результаты ниже разделены по датам.

Для проверки источника отдельно:

```bash
.venv/bin/python -m backend.sources.cian --city Казань --rooms 2 --budget 9000000 --pages 1
```

Циан может сначала ответить 307 на тот же адрес с `Set-Cookie`. Повторный запрос выполняется в той же HTTP-сессии, сохраняя cookies. Капчи не решаются; если выдача недоступна, используются реальные срезы/база с указанием источника. Повторные отказы ограничены паузой в минуту для города/рынка, весь запрос — 35 секундами. Повреждённый срез игнорируется, новые срезы записываются атомарно.
