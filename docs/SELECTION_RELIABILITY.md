# Сравнение подборки, восстановление и прогресс

## Что показало расследование

В диалоге из скриншотов «среди этих двух какая выгоднее за кв м» стало
`price_per_m2 <= 2`. Пустой результат заменил показанные квартиры, а следующая
команда работала уже с пустой областью `shown`. Это ошибка интерпретации,
усиленная ошибкой управления состоянием; процесс сервера не падал.

Отдельно неудачно разобранная реплика оставалась в очереди нового ввода.
Вопрос «А что надо то?» повторно разбирался вместе с ней и снова получал
одинаковый отказ. Разбор 1–2 комнат также допускал лишнюю студию.

Строгая JSON Schema проверяет форму, но не смысл чисел. Прежние проверки
исполнителя с готовыми ответами модели не обнаруживали эти ошибки.

## Изменения

Главный агентский цикл остаётся одним. На входе определяется тип нового
сообщения через function calling: изменение условий, чтение подборки, вопрос,
намерение звонить или пауза. Эти функции не являются
дополнительными бизнес-инструментами и ничего не исполняют. Исполнение
по-прежнему использует реестр инструментов основного агента.

Явный флаг изменения условий отличает составной запрос от обычного чтения.
Для изменения профиля и составного отбора отдельный проход извлекает список
фактов с цитатами нового сообщения. В его контексте нет прежних карточек и
служебных реплик интерфейса. JSON проверяется кодом по схеме; десятки
неназванных nullable-полей не заполняются. Неподдержанное свойство — тоже
данные запроса, а не отдельное намерение. Географические сущности проверяются
по исходным словам и каталогу.
Комнатности 1–5 отделены от явного разрешения студии. Для чтения ещё не
существующих результатов функция недоступна.

Команда чтения описывает цель: отбор, сравнение, статистика или ещё варианты;
область, количество, порядок и показатели. Числовых предикатов в ней нет.
Запрошенное количество связано с цитатой нового сообщения; сохранение
прежнего порядка задаётся отдельно. Исполняемый запрос собирает Python.
Новый фильтр квартиры применяется через изменение профиля.
Числовые предикаты дополнительно проверяются по числам нового сообщения;
числа в словесной форме остаются задачей смыслового разбора. Именованное
условие и универсальный фильтр одного свойства заменяют друг друга при
изменении или снятии ограничения.

`show_selection` использует принятую команду без повторного придумывания
аргументов основным агентом. Сравнение и статистика рассчитываются кодом,
отвечают в чат и сохраняют карточки. Сравнение показанных объектов использует
точный снимок, включая восстановление после перезапуска.

Новый результат сначала вычисляется и только затем сохраняется. Пустой отбор
не заменяет последнюю рабочую подборку и её команду. Старые пустые SSE-события
тоже не стирают карточки при воспроизведении истории. При смене профиля старые
карточки сохраняются как предыдущий результат, но не дают разрешения на звонок.

Ошибка разбора завершает обработку неудачного ввода. Следующий вопрос не
перезапускает его. Агент сообщает об ошибке обработки на своей стороне;
действительная неоднозначность вызывает предметный вопрос о городе, улице,
сумме или объекте. Последняя ошибка передаётся в контекст обычных ответов.

Прогресс SSE обновляется по фактически полученным пакетам объявлений и
результатам проверки инфраструктуры: получено, предварительно подходят,
подтверждено, ещё не проверено. Искусственных счётчиков нет. Интерфейс меняет
тот же узел статуса, сохраняя карточки и карту.

## Как проверять следующие изменения

```bash
.venv/bin/python -m unittest discover -s tests
# Настоящая модель, синтетический контекст; расходует квоту, без поиска/звонков:
.venv/bin/python -m tests.e2e.semantic_eval
# Отдельная БД, настоящий агент/модель и синтетические объявления:
.venv/bin/python -m tests.e2e.flexible_server --port 8797 --live-llm
.venv/bin/python -m tests.e2e.live_reading_recovery --base http://127.0.0.1:8797
.venv/bin/python -m tests.e2e.live_selection_followups --base http://127.0.0.1:8797
.venv/bin/python -m tests.e2e.live_flexible_cases --base http://127.0.0.1:8797
.venv/bin/python -m tests.e2e.live_controls --base http://127.0.0.1:8797
.venv/bin/python -m tests.e2e.live_dialogue_cases --base http://127.0.0.1:8797
```

Корпус модели проверяет 30 формулировок: опечатки, сравнения, область выдачи,
короткую коррекцию количества, статистику, комнатность, неоднозначную
территорию, вопросы об ошибке, неподдержанные условия, полные начальные запросы
и сочетание фильтра сдачи с отбором. Связанный сценарий
проверяет весь переход от трёх выгодных к двум большим, сравнению и следующему
отбору, а также восстановление после пустого результата и уточнения города.

Проверки модели нужны отдельно от тестов кода. Каждый новый сбой следует
сначала добавить в воспроизводимый сценарий, затем исправлять и прогонять
соседние сценарии. Успешный корпус не гарантирует понимания любой будущей
фразы; неверный результат должен останавливаться до изменения рабочего
состояния, сохраняя понятный способ продолжения.
