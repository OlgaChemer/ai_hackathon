# Критерии подбора квартиры

Как агент собирает критерии у клиента и как решает, что показать.
Реализация — `backend/agent/criteria.py`, вопросы и разбор текста — `backend/agent/prompts.py`
и `backend/agent/tools.py`, шаг «Запрос» и поиск — `backend/agent/orchestrator.py`.

## Правило

1. Клиент описывает квартиру своими словами — из текста вытаскиваются все названные критерии.
2. Агент доспрашивает недостающее: сначала **5 обязательных**, потом **3–5 дополнительных**
   («не важно» — тоже ответ, критерий считается заданным, но не ограничивает выдачу).
3. Каждое объявление получает один из трёх исходов:

| Исход | Когда | Что делает агент |
| --- | --- | --- |
| **Подходит** | ни одного явного промаха, подтверждено ≥ 70% критериев | показывает в топ-10 |
| **Нет данных** | явных промахов нет, но по части критериев в объявлении молчат | показывает с пометкой «нет данных: … — могу позвонить и уточнить» |
| **Не подходит** | есть явный промах: в объявлении прямо сказано «без лоджии», «первый этаж», «требует ремонта» | не показывает вообще |

4. Клиенту выводится **топ-10**: сначала полные совпадения, потом варианты с пробелами,
   внутри — по цене относительно справедливой и пожеланиям.

## Пример с лоджией

- Клиент: «обязательно с лоджией».
- В объявлении про лоджию **ничего нет** → исход «нет данных», квартира показывается,
  в карточке пометка «Нет данных: лоджия/балкон — могу позвонить продавцу и уточнить».
- В объявлении написано **«без лоджии»** → исход «не подходит», квартира не показывается,
  даже если остальные девять критериев сошлись.

## Пять обязательных

| Критерий | Поле профиля | Значения |
| --- | --- | --- |
| Город | `city` | Москва, Санкт-Петербург, Казань, Новосибирск, Екатеринбург, Нижний Новгород, Краснодар |
| Бюджет | `budget_max` | рубли; перебор до +5% допустим — его можно сторговать |
| Комнаты | `rooms` | 0 (студия), 1, 2, 3, … |
| Состояние | `condition` | `ready` (заехать сразу) · `cosmetic` · `repair` (под ремонт) · `any` |
| Метро | `metro_max_minutes` | минуты пешком (транспорт считается ×2) или `metro_any` |

## Дополнительные (минимум 3, максимум 5)

| Критерий | Поле профиля | Что проверяем |
| --- | --- | --- |
| Этаж | `not_first_floor`, `not_last_floor` | этаж и этажность из объявления |
| Площадь | `area_min`, `kitchen_min` | общая площадь и кухня |
| Дом | `material`, `year_min` | материал и год постройки |
| Пожелания | `features` | лоджия/балкон, парковка, кладовка — по тексту объявления |
| Инфраструктура | `infra` | школа / садик / парк — влияет на ранжирование |
| Сроки | `timeline` | месяц / квартал / присматривается — влияет на темп и финансы |

## Как считается процент

- Знаменатель — все критерии, которые клиент задал и которые в принципе проверяемы
  по объявлению: «совпало 7 из 10».
- Критерий без данных в объявлении считается **неподтверждённым**, а не проваленным:
  он снижает процент, но не выбрасывает квартиру из подборки.
- «Не важно» не входит в знаменатель вообще — иначе клиент сам себе занижал бы совпадение.
- Явный промах обнуляет вариант независимо от процента: 9 из 10 не спасают квартиру
  без лоджии, которую клиент просил.

## Если подходящих меньше десяти

Показываются варианты с пробелами («нет данных») — тоже с пометкой. Если и таких нет,
агент честно говорит, что по всем критериям не подошло, и предлагает смягчить условия
(этаж, площадь, состояние, метро, лоджия).

## Что не подключено

- **Новостройки**: источник — только вторичка (`cat.php`), раздел ЖК с застройщиками
  и сроками сдачи требует отдельного парсера.
- **Стоп-факторы** (окна на дорогу, обременение) в объявлении не проверить —
  они уходят в чек-лист звонка продавцу.

## Локация: что рядом с домом

Считается по карте, а не по словам в описании объявления (`backend/sources/places.py`).

- берём координаты объявления (`lat`/`lng` от Циана) и ищем ближайшие **садик, школу, парк**
  в радиусе 1–1,2 км;
- расстояние — по прямой, время пешком — 80 м/мин (≈4,8 км/ч);
- в карточке: «Рядом: школа 280 м (4 мин) · садик 500 м (6 мин)» и ссылка **на карте**
  (`yandex.ru/maps` по координатам, без ключа);
- на вопрос в чате «а рядом есть садик?» агент отвечает по уже показанным карточкам;
- критерий «школа/садик рядом»: до 1 км — подтверждён, дальше — явный промах,
  нет данных с карты — «неизвестно», квартиру не наказываем.

Источники идут цепочкой:

1. **2GIS** (`catalog.api.2gis.com`, ключ `TWOGIS_API_KEY`) — основной источник,
   работает с российских адресов. С зарубежного IP 2GIS отдаёт 403 на сайте и молча
   висит на API; тогда один таймаут — и до конца жизни процесса источник помечается
   недоступным, чтобы не тормозить подборку. Состояние видно в `/api/health`:
   `places.provider` = `2gis` | `osm` | `auto`.
2. **OpenStreetMap / Nominatim** — бесплатно, без ключа, без гео-блокировки. Основной
   источник в текущем окружении (у машины нидерландский IP).

Кеш ответов — месяц, запросы не чаще одного в секунду, бюджет на подборку — 12 секунд.
Ключ Яндекса (`YANDEX_MAPS_API_KEY`) на `/1.x` и Places API даёт `403 Invalid api key` —
похоже, это ключ JavaScript API для виджета карты; он лежит в `.env` на будущее.
