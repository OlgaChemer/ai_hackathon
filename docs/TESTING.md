# Проверка защиты и обычных сценариев

Живые проверки развёрнутого сайта и порядок отката описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

```bash
.venv/bin/python -m unittest discover -s tests -t .
```

`tests/test_guard.py` проверяет:

- известные атаки, обфускацию и обычные фразы про ключи от квартиры и защиту персональных данных;
- отказ до вызова модели, включая восстановленный диалог;
- обход через HTTP-подтверждение карточки, повторный корректный ответ и незакрытую карточку;
- фильтрацию карточек, фактов, ключей словарей, истории, памяти и отсутствие исходных секретов в аудите;
- отсутствие внешних строк в системных промптах агента, Q&A, переговорщика, симулятора продавца и извлечения фактов;
- отказ выполнить неверные аргументы инструментов, сброс согласий при смене условий и лимит вызовов внутри одного ответа;
- раздельные лимиты маршрутов, смену cookie/IP, очистку счётчиков и сохранение базы;
- обычное подтверждение семьи без детей, где возраст передаётся как null.

## Сделки без сети

```bash
# Терминал 1: отдельная временная база, тестовая модель и сохранённые объявления.
.venv/bin/python -m tests.e2e.server --port 8791
# Терминал 2:
.venv/bin/python -m tests.e2e.scenarios --base http://127.0.0.1:8791
```

Четыре сценария доходят до подписания: наличные, накопления/маткапитал, ипотека, смешанный рынок. `PolicyLLM` используется только в тестах; в продукте режима работы без LLM нет.

Сохранён браузерный сценарий из `nas_features`, адаптированный к текущим правилам:

```bash
# Требует отдельно установленного Playwright и Chromium.
.venv/bin/python -m tests.e2e.browser_flow --base http://127.0.0.1:8791
.venv/bin/python -m tests.e2e.ui_regressions --base http://127.0.0.1:8791
```

## Настоящая модель

```bash
.venv/bin/python -m tests.e2e.live_guard
```

Использует провайдера и ключ из `.env`, делает до четырёх платных запросов. Передаёт только синтетические данные и не выполняет инструменты, не звонит и не обращается к Циану. Проверяет обычный запрос, извлечение инструкций, подмену бюджета через объявление и попытку продавца узнать лимит клиента. Проверки маркеров и чисел ограничены: перефразированная утечка требует отдельной ручной оценки.

`ui_regressions` проверяет передачу полей формы и новую главную → запрос → подборку на мобильной ширине, сообщение при отказе плиток, 2ГИС → OSM с сохранением меток и жизненный цикл аудио. Аудиоконтекст и SIP подменены: тест проверяет запуск до сетевых ожиданий, восстановление после прерывания и совместное использование контекста записью; настоящих звонков не делает. Он не заменяет проверку на физическом iPhone. Изображения плиток в этом тесте подменены, доступность реальной подложки проверяется отдельно.

`test_cian_resilience` воспроизводит серверный 307 с cookies, ограничивает циклы редиректов и проверяет паузу после отказа, дедлайн, резервный срез и ошибку записи. `test_gigachat_state` учитывает старую серверную память с полем `provider_state`. Аудиопроверка также использует Safari-совместимый MP4/AAC и проверяет освобождение контекста микрофона.

Для ручной проверки настоящих плиток с ключом из `.env` запустите отдельный тестовый сервер с `--live-map`. Это расходует квоту 2ГИС; модель и объявления остаются подменены, внешние звонки не выполняются.

Проверка 01.11.2026: 132/132 модульных и интеграционных теста, 4/4 сценария сделок через API, 26/26 проверок браузерного сценария и 4/4 группы UI-регрессий. Дополнительно живой GigaChat-2-Max прошёл синтетический сценарий до подборки (объявления подменены, без звонков): одна карточка типа жилья, подтверждение рамок, поиск, подборка. 2GIS вернул школу и парк для тестовых координат Казани; настоящие растровые плитки проверены отдельно в браузере через локальный endpoint. Эти разовые прогоны проверяют интеграцию, но не гарантируют стабильность внешних сервисов.
